# 错题本 · 本地代码骨架（未部署、未上线）

这是一份按用户对齐下来的设想做的纯前端骨架，方便以后放 GitHub Pages，不需要复杂构建步骤。
**当前状态：只建了本地文件，没有推送到 GitHub，没有创建 Supabase 项目，没有使用任何密钥，不能直接给朋友用。**

## 建了哪些文件

- `index.html` —— 登录页：账号密码注册登录，邮箱选填，各人数据独立；一个设备登录一次后保持登录，只有主动退出或清浏览器数据才重填。
- `upload.html` —— 录错题：直接拍照（`capture`）和上传已有图片；照片只预览、不存；上传后用透明色方框框出题目，点方框选错题，不用填题号；只有一道题时勾选单题即可；手动补框；识别不清提示重拍；提取后校对题干选项、确认正确答案和学科分类；大题型分选择题、判断题、主观题。
- `bank.html` —— 错题库：按学科自动分类（学科可手动改）、标错因并看薄弱统计、按试卷/日期分组、重复上传提醒（占位）、录错可删、导出打印、点星星收藏到易错题、改解析（标手动改过、不锁定）、一键复制解析。
- `practice.html` —— 练习：练习前自选数目（五的倍数、最多 50 个）；从未掌握题里随机出题；答时先不显示答案和解析，答完再显示；连续做对三次标为已经会了，练习里不再出现但库里仍可见且格外标出；错一次计数清零；已掌握复查和按知识点生成同类题为占位。
- `notebook.html` —— 笔记本：新开的一页，自己粘贴知识点，和难题无关；默认黑色，标记重点时可按条改成红或蓝。
- `errors.html` —— 易错题：错题库点星星收藏的特别薄弱的题，和笔记本并列、互不干扰。感悟页已按用户决定去掉（`insights.html` 仍留在本地目录里、已不再链接，待确认后删除）。
- `admin.html` —— 管理后台：仅事先标定的主人账号可见，能看谁登录、什么时候用、用了多长时间；朋友默认普通用户，看不到；看不到朋友的错题内容。
- `styles.css` —— 风格：浅蓝打底、粉色为主、亮粉强调、薄荷绿小面积点缀、白色提亮，可爱贴纸拼贴感；另含装饰层样式（边缘散落、低密度、不拦截点击）。
- `decorations.js` —— 随机小元素装饰（新增占位）：每次刷新随机选 4-6 个小元素（手机上最多 4 个），随机散落在页面左/右边缘和角落空白处，尺寸 26-40px、透明度偏低、轻微随机旋转；装饰层 pointer-events:none、正文在上层，不遮挡正文和按钮，不喧宾夺主。只取参考图周围小元素的类别（小猫、蝴蝶结、草莓、星星等），不取中间的“吉级天使”大字；当前用本站配色像素风占位符号实现，没有把原图文件复制进本站，也没有把整张大图当背景铺满，更不是已用了原图素材。以后如用户确认换成原图裁切小元素，需另行放入经确认的裁切小图再替换。
- `config.js` —— 配置占位：Supabase 地址/key、管理员账号均为占位符，无真实密钥。
- `app.js` —— 共享骨架逻辑：未配置 Supabase 时用浏览器 localStorage 做演示，数据只存本机。

## 每个页面怎么走一遍流程（骨架演示）

1. `index.html`：填账号、密码，邮箱可填可不填，点“注册 / 登录”→ 跳到录错题页。退出用“退出登录”。
2. `upload.html`：点“直接拍照”或“上传已有图片”→ 照片预览上出现透明色示例框 → 点方框选错题（单题勾选单题）→ 没框住的题点“手动补框”→ 点“识别所选题目”→ 骨架用确认框模拟“识别清楚 / 识别不清”分支：识别不清时显示重拍提示，不能继续；识别清楚时进入校对 → 改题干、选项、正确答案、学科、解析类型、错因 → 点“确认无误，保存到错题库”→ 跳到错题库。
3. `bank.html`：按学科筛选、只看星标/只看已经会了的题 → 看薄弱统计 → 对每道题点星星收藏到易错题、改解析、复制解析、手动改学科、删除；点“导出打印”走浏览器打印。
4. `practice.html`：选数目（5、10、……、50）→ 点“开始练习”→ 随机题出现，先不显示答案 → 选答案提交 → 答完显示正确答案、解析和连续做对次数 → 连续三次变“已经会了”，错一次清零 → 点“下一题”；“已掌握复查”和“生成同类题”目前是占位提示。
5. `notebook.html`：粘贴知识点 → 按条选黑/红/蓝色，默认黑色。
6. `errors.html`：看星标收藏的易错题。
7. `admin.html`：未配置管理员账号或当前账号不是管理员时，只显示“仅管理员可见”提示；配置后且管理员账号登录时，才显示演示登录记录表。

## 部署需要用户补哪几项（缺一不可，缺了就不能真正跑通）

1. **Supabase 项目地址和 anon key**：用户自己在 Supabase 创建项目后，把项目地址和 anon key 填进 `config.js`（不要填 service_role key，不要把 key 写进公开代码以外的聊天记录）。
   建议先建的表（骨架未创建，仅供部署时参考，不在本骨架里自动建）：
   - `profiles`：账号、角色（admin / user）、邮箱（选填）、管理员标定字段。
   - `questions`：所属用户、大题型（选择题/判断题/主观题）、题干、选项、正确答案、解析、解析是否手动改过、学科、解析类型、错因、批次（试卷/日期）、星标、已掌握、连续做对次数、创建时间。
   - `login_records`：账号、登录时间、最后活动时间、用时（供管理后台统计）。
   - 行级安全策略（RLS）：每人只能读写自己的 questions / insights；login_records 只有管理员可读。
2. **DeepSeek 密钥**：不要写进前端代码、不要写进 GitHub 仓库。以后放 Supabase Secret，写一个 Supabase Edge Function（例如 `explain`）做代理：前端把题干、选项、正确答案、解析类型发给 Edge Function，Edge Function用保密密钥调 DeepSeek，返回解析；同类题生成也走同一个后端通道。当前骨架的 `EXPLAIN_FUNCTION_URL` 为空，`explainPlaceholder()` 只返回模板，不是真实调用。
3. **GitHub 仓库名**：用户自己在 GitHub 创建仓库（例如 `photo-wrong-question-site`，名字由用户定），把本目录文件推上去后，在仓库设置里开 GitHub Pages（分支 main、根目录），得到公开链接再发给朋友。**本骨架没有推送，仓库还没建。**
4. **管理员账号**：把主人自己的注册账号（用户名或邮箱）填进 `config.js` 的 `ADMIN_ACCOUNT`，并在 Supabase 的 profiles 里把该账号角色标为 admin。真实校验必须以后端角色为准，不能只靠前端隐藏管理页。
5. **邮箱找回（选填）**：如果要让填了邮箱的用户能找回密码，需在 Supabase Auth 里开邮箱验证/密码重置，并配好重置链接指向部署后的网站地址；没填邮箱的账号没有邮箱找回途径。

## 目前哪些环节是骨架占位、还不能直接跑通

- **真实注册登录、数据同步、各人隔离**：未接通 Supabase Auth / 数据库，当前只用 localStorage 演示，换设备、换浏览器数据就不在，也不能给朋友用。
- **真实题目框选与 OCR 识别**：上传页的方框是两个演示框，手动补框是简化版（点一下加框），不是真实题目切分；真实识别、识别置信度判断、识别不清自动提示重拍，都需接 OCR / 视觉模型后实现；当前用确认框模拟不清分支。
- **真实 DeepSeek 解析与同类题**：`explainPlaceholder()` 只返回模板；真实解析、定量/定性两类风格、学科自动分类、正确答案推断，都需 Edge Function + DeepSeek 接通后实现。
- **重复上传提醒**：当前保存时没有真实比对题干，提醒是待实现占位。
- **已掌握复查排期**：抽查间隔（例如一两周）未最后定死，复查按钮目前只是占位提示，没有自动排期。
- **邮箱找回、一键退出所有设备**：当前是占位按钮/提示，需 Supabase Auth 的密码重置与会话吊销才能实现。
- **管理后台数据**：登录记录表是演示数据，真实登录时间、用时需后端在登录/活动时记录。
- **导出打印**：当前走浏览器打印，正式的导出 PDF / 打印卷格式待部署后按需做。

## 风格与人物说明（按用户对齐）

- 先只用配色和风格：浅蓝打底、粉色为主、亮粉强调、薄荷绿小面积点缀、白色提亮，可爱贴纸拼贴感。
- **不要把用户参考图里的人物直接嵌进去。** 人物规则：三个一起搬、好看不突兀才搬、否则不搬，待用户看效果再定。也就是说，先不上人物，等用户确认效果后，再决定是否三个一起放、放哪里。

## 本地打开方法（仅看骨架样子）

直接用浏览器打开 `index.html` 即可走一遍上面的流程；因为没有后端，所有数据只存在本机浏览器，清除浏览器数据后演示数据会消失。这不是部署，也不是上线。
